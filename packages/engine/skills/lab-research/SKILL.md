# Research at a lab

1. **Find what the lab offers.** `find_tools` with words like "papers", "datasets", "library", "runs", "lineage".
   The person's data scopes say which data they may use; data stays at the lab and is passed by reference.
2. **Literature.** Search the lab's library first, then the web. Keep a reference list with DOIs or links, and say
   which claims come from which source. Read the methods and results, not only abstracts, before relying on a paper.
3. **Analysis in the sandbox.** Write scripts in the lab's sandbox, next to the data. Record package versions and
   seeds; save results with their inputs' identifiers so each number can be traced back.
4. **Long work.** Plan in steps with clear checkpoints (`plan`). Where the lab offers runs, a long analysis can go on
   at the lab while the person is away; say what will run and how they'll see the result.
5. **Traceability.** End with what was asked, what was found, the data and tools used (with versions and
   identifiers), what was assumed, and what to check next. `el session package` keeps the whole record.
